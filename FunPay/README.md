# FunPay

MVP игрового маркетплейса. Пользователь регистрируется, создает объявление, другой пользователь оформляет заказ и пишет продавцу.

## Структура

- `backend/` - API, БД, модели, сервисы, логи.
- `frontend/` - сайт, страницы, компоненты, ассеты.
- `docs/` - описание проекта, планы, БД, API и задачи команды.

## Главное за неделю

1. Каталог.
2. Объявления.
3. Заказы.
4. Чат.
5. Авторизация.

## План

| День | Что делать |
| --- | --- |
| 1 | Создать проект, подключить БД, сделать модели: User, Game, Category, Product, Order, Message |
| 2 | Сделать регистрацию, логин, JWT-токен, роли User/Admin |
| 3 | Сделать каталог: игры, категории, список объявлений, страница объявления |
| 4 | Сделать создание/редактирование/удаление объявления |
| 5 | Сделать оформление заказа и статусы: Created, InProgress, Completed, Cancelled |
| 6 | Сделать простой чат между покупателем и продавцом внутри заказа |
| 7 | Доделать профиль, админку, дизайн, багфиксы, деплой/запуск |

## Таблицы

| Таблица | Поля |
| --- | --- |
| Users | Id, Nick, Email, PasswordHash, Role, CreatedAt |
| Games | Id, Name, ImageUrl |
| Categories | Id, Name |
| Products | Id, UserId, GameId, CategoryId, Title, Description, Price, Status |
| Orders | Id, ProductId, BuyerId, SellerId, Status, CreatedAt |
| Messages | Id, OrderId, SenderId, Text, CreatedAt |

## Не делать в MVP

- Реальные платежи.
- Сложный внутренний баланс.
- Автовыдачу товара.
- Систему споров.
- Верификацию продавцов.
- Уведомления.
- Избранное.
- Сложные фильтры.
